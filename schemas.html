Annexe · Méthode

Comment les schémas sont faits

Les seize schémas du dossier sont dessinés par un programme, à partir des réponses du questionnaire. Aucun chiffre n'y est tapé à la main : si une réponse change, une commande redessine tout.

Le principe, en une chaîne

  1. Les réponsesl'export du questionnaire, nettoyé par le squelette du cours ; il reste sur l'ordinateur du groupe
  2. Les calculsun script Python recalcule chaque chiffre : parts, tests, intervalles, régressions
  3. Le dessinchaque schéma est une fonction Python qui écrit un dessin SVG, du texte
  4. La pagele script place chaque dessin dans la page HTML, entre deux balises
  5. Le siteGitHub Pages publie les pages ; aucune bibliothèque à charger

Le programme tient dans un seul fichier, annexes/fabriquer_schemas.py, d'environ 700 lignes. Il ne contient aucune réponse individuelle : il les lit sur l'ordinateur du groupe, et seules des moyennes et des parts arrivent dans les pages.

Pourquoi un dessin SVG plutôt qu'une image ou une bibliothèque

Un SVG, c'est du texte

Un schéma SVG est une suite d'instructions lisibles : « un rectangle ici, de cette hauteur, de cette couleur ». Un programme peut donc l'écrire, comme il écrirait une phrase. Il reste net à toutes les tailles, sur un écran comme à l'impression.

Aucune dépendance

Le site n'appelle aucune ressource externe, ni police, ni bibliothèque de graphiques. Les schémas sont écrits dans la page elle-même : ils s'affichent même sans connexion, et le site reste léger.

Des chiffres traçables

Chaque hauteur de barre est calculée à partir des réponses, au moment où le script tourne. Un chiffre du schéma ne peut donc pas contredire un chiffre du tableau : ils sortent du même calcul.

Accessible

Chaque schéma a un titre et une description lus par les lecteurs d'écran, chaque barre et chaque point une info-bulle, et chaque graphique son tableau de chiffres, « Voir les chiffres du schéma ».

Le code, pas à pas

1. Une échelle : passer d'une valeur à un pixel

Tout graphique repose sur une règle de trois. Pour une part de 0 à 100 % dessinée entre le bas du cadre (y = 250) et 210 pixels plus haut, la position d'une valeur v est :

y = lambda v: base - plot * v        # 0 % en bas (y = 250), 100 % en haut (y = 40)
y(0.45)   # → 155,5 : le haut de la barre de la version A

2. Une brique : la barre

Chaque barre est un chemin SVG : on part de la ligne de base, on monte, on arrondit les deux coins du haut de 4 pixels, on redescend. Le texte entre <title> devient l'info-bulle au survol.

def barre_v(x, y_base, hauteur, largeur, couleur, info):
    """Une colonne posée sur la ligne de base, bout arrondi de 4 px en haut, carré en bas."""
    r = min(4, hauteur / 2, largeur / 2)
    y = y_base - hauteur
    chemin = (f"M{x},{y_base} V{y + r} Q{x},{y} {x + r},{y} H{x + largeur - r} "
              f"Q{x + largeur},{y} {x + largeur},{y + r} V{y_base} Z")
    return f'<path d="{chemin}" fill="{couleur}"><title>{info}</title></path>'

3. Un schéma : des briques et des chiffres calculés

Le schéma 5 (la part qui choisit Michelin) assemble deux barres, deux intervalles de confiance et une ligne à 50 %. Les chiffres ne sont pas écrits : ils viennent du calcul fait juste avant, sur les réponses.

kA, nA = int(A.m.sum()), len(A)                              # 23 Michelin sur 51 en version A
icA = proportion_confint(kA, nA, method="wilson")            # intervalle de confiance à 95 %
c.append(barre_v(cx - 14, base, plot * kA / nA, 28, "#A86B00", "Version A : 45 %"))
c.append(L(cx, y(icA[0]), cx, y(icA[1]), ENCRE, 1.5))        # le trait de l'intervalle

4. La page : deux balises, et le script remplit l'entre-deux

Dans la page HTML, le texte écrit par le groupe entoure deux balises invisibles. Le script remplace ce qu'il y a entre elles par le schéma ; le texte autour ne bouge pas.

<!-- dans client.html -->
<!-- schema:choix -->
   ... le script écrit ici le schéma 5 ...
<!-- /schema:choix -->

# dans le script
motif = re.compile(r"(<!-- schema:choix -->)(.*?)(<!-- /schema:choix -->)", re.S)
html = motif.sub(lambda m: m.group(1) + schema + m.group(3), html)

5. Refaire tous les schémas

Depuis le dossier site/, avec l'environnement Python de l'analyse (pandas, scipy, statsmodels), une commande suffit :

../analyse-projet-prix/.venv/bin/python annexes/fabriquer_schemas.py
# client.html : 16 schéma(s) placé(s)
# synthese.html : 1 schéma(s) placé(s)
# Test A/B : 45 % contre 67 %, p = 0,024 ; puissance 62 % ; point mort de l'effet 13,3 points

L'ocre (#A86B00) et le bleu (#27509B) ont passé un validateur de palette : un contraste suffisant sur fond blanc, et un écart de couleur assez grand pour qu'une personne daltonienne les distingue, quel que soit le type de daltonisme. Le bleu clair essayé d'abord échouait au contraste : il a été écarté.

Comment ils ont été faits si vite

Le programme a été écrit avec Claude Code, l'IA qui code présentée au cours d'Analyse de données (CM 1) : on décrit ce qu'on veut, l'agent écrit le code, le lance, regarde le résultat et corrige. La méthode a tenu en quatre temps :

  1. Décrirepour chaque étape de l'analyse, le schéma qui répond le mieux à la question, et la phrase qu'il doit permettre d'écrire
  2. Factoriserune dizaine de briques réutilisables (barre, point, flèche, boîte, axe, échelle) plutôt que seize dessins écrits à la main
  3. Regarderchaque schéma est ouvert dans le navigateur, sur ordinateur et sur téléphone ; les étiquettes qui se chevauchent sont déplacées
  4. Recompterles chiffres des schémas sont comparés à ceux du classeur Excel de l'analyse, calculés par un autre chemin

Le gain de temps vient de la factorisation : une fois la brique « barre » écrite, un nouveau graphique en barres coûte quelques lignes. Et comme tout est recalculé à chaque fois, corriger une erreur dans les données ne demande pas de redessiner à la main.

Ce que l'IA n'a pas fait. Elle n'a choisi ni les hypothèses ni la conclusion, et n'a inventé aucun chiffre : chaque valeur vient des réponses du questionnaire ou du dossier du groupe, et peut se retrouver dans le classeur d'analyse. Le groupe doit pouvoir expliquer chaque schéma à l'oral.
